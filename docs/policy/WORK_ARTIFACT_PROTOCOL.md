# HALO-9 — Work使用とGitHub成果保存の共通規則

**2026-10-24 JST（ユーザーの新しい方針を文書化）**
**この文書のDraft PRがmainへマージされるまでは、提案ブランチ上の文書である。**
目的：継続開発でWorkを適切に活用し、成果データが各チャットに閉じ込められずGitHubで比較・再検証できるようにする。

## 1. Work利用の扱い

ユーザーが2026-10-24に「今回ほどではなくとも多少の効果的なWorkの使用を今後も許可」と明示。

- **限定的・効果的なWork利用を今後の研究で認める。** 特に実3D、複数視点レンダリング、ローカルGUI操作、複雑なファイル管理・比較検証などでChatより明確な利点があるときに選ぶ。
- 毎回無条件でWorkを使用すること、作業を無制限に拡大すること、使用量の消費を目的とすることは認めない。
- 何をするのか、どのデータに書き込むのか、原本を保護する方法、見込まれる価値を簡潔に明示する。UIでWorkへの切替がユーザーにより拒否された場合は、そのセッションではWorkを使用しない。
- 公式Minecraftワールドの施工・原本書込・Freeze変更・保護資産の破壊的変更・外部への機密転送・大掛かりなインストール・課金等の高影響行為には、なお**別途明示承認**が必要。
- 3D研究は隔離コピー、検査済み研究ブランチを基本とし、正式美術採択・原本と同一視しない。
- Workが使えないときには、Chatから安全にできる設計・監査・GitHub記録を進め、実機を操作したと偽らない。

## 2. 成果物のGitHub優先保存

Work、Chat、Codex、他社AIによるHALO-9研究で以下が発生した場合は、利用可能な手段で**GitHubに直接保存することを優先**する。

| 種別 | 保存候補 |
|---|---|
| 3D編集原本 | BLEND、Houdini/HDA、Unrealプロジェクトの適切なソース構成、USD等 |
| 交換可能3D | GLB、GLTF、OBJ、必要な素材 |
| 画像 | 同一実3Dからの正面・斜視・側面・背面・俯瞰・重要内部、必要な断面、同一条件比較 |
| 再制作 | 制作コード、生成規則、使用したアセット情報・依存・バージョン |
| 検証 | JSON/CSV、再読込・幾何・経路・座標・多視点・アート審査の結果 |
| 審査 | 日本語レポート、判断根拠、現状のHOLD/REJECT/ACCEPT区別 |
| 最新参照 | 研究ID単位の `latest.json` または `manifest.json` とコミットSHA |

研究は独立ブランチ・専用フォルダに保存し、他系統の成果を無断変更しない。共有ブランチが他セッションで更新されている場合、強制push・上書きを避けて独立した新ブランチで衝突を防ぐ。

**GitHubでの保存を成功と報告する条件**：少なくとも作成した成果物パスがGitHub上で読戻し可能で、どのブランチ・コミットかが分かること。元のローカルZIPだけではGitHub保存済みにならない。

## 3. 実物・品質の追跡

- 表示用画像と、編集可能な実3Dモデルの出典が対応していることを必ず記録する。
- 組立可能なモデル・手続き生成ルール・検証用プロキシ・本格アート・正式採択済みモデルは別の状態として扱う。
- REJECT/HOLDの失敗形状も研究履歴として保存し、再利用可能な制作技術だけを引き継いでよい。
- 全10km最終完成基準は `CITY_MASTER_3D_STANDARD.md` が優先。一般建物の私的室内以外の詳細設計は必須。
- 幅・高さ・三角形数・画像枚数・QA PASSのみで美術合格にしない。

## 4. サイズ・プライバシー・失敗対応

- GitHubのGitオブジェクト制限・リポジトリ容量・LFS等を考慮し、数百MB規模を通常コミットへ無理に格納しない。必要な場合はGit LFSやバージョン付き別保管方法を適切に設定し、その場所をGitHubから追跡可能にする。
- 元モデルやZIPがGitHubへ自動送信できなかった場合は、**未保存として正直に列挙**する。代わりにmanifest/コードだけ保存できた場合もファイルごとに状態を記録する。
- ユーザーに毎回ZIPダウンロード／再アップロードを求める運用を避ける。可能ならAIがアップロードを行うが、能力・権限がなければ制約と最小の操作を明示する。
- ユーザーの個人情報・端末固有絶対パス・設定ファイルの秘密・認証情報は公開GitHubへ無断アップロードしない。
- GitHubへの保存を優先することは、個人情報や原本の公開・世界の施工権限を意味しない。

## 5. チャット／Workの引き継ぎ

新しいセッションはまず **main/docs/policy/START_HERE.md** から公式方針を読み、次に研究ブランチの `latest.json` と最新HEADを確認する。毎日長文のプロンプトを作り直す必要はない。

共通規則はすべてのHALO-9研究に適用。特定のart/a〜dに割り当てられたAIは、そのブランチ以外を勝手に更新しない。中央監督は比較と統合を担当し、正式ルールの変更にはユーザーの明示判断を記録する。
