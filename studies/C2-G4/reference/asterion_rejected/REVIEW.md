# 天綾宮 アステリオン — MASSING REINVENTION

CELESTIAL HALO-9／Chat C／2026年10月22日／独立研究

**結論：主質量は根本的に再構成した。旧案からの改善は認めるが、圧倒的な未来文明の主役建築としての美術合格には未達。正式採択・施工HOLD。細密化は停止する。**

## 1. 比較した二案と選定

二案の全文は`CONCEPTS.md`に収録した。

- **案I「三つの空洞を交織する都市宮」**：縦の居住門、横の天空盆地、斜めの都市峡谷を統合する。同じ断面の三本の帯を交差させる設計を廃し、異なる都市空間の形式を交差させる。
- **案II「偏心する三つの都市殻」**：高度と位置の異なる中空都市核へ質量を集中し、公共峡谷で結ぶ。巨大な内部都市をつくりやすい一方、三つの建築の集合に分離して見える懸念が強い。

案Iを一棟としての輪郭と内部体験の変化に有望と判断し、低詳細の実3Dを制作した。案IIのGLBは制作していない。選定時の有望性と、実3D確認後の美術判定は分けている。

他モデルの具体的な外形は参照・転用していない。取り入れたのは、全体断面から都市空間を考えること、主構造から地盤・施設への関係を追えるようにすること、誤読を主構造から修正すること、という設計・反復の原理である。

## 2. 新しい三都市体

### 天稜：都市を内包する巨大な居住門

前後の厚い居住壁と、それらを覆う深い外周屋根で都市の断面をつくる。主たる外形は床の反復ではなく、地上から上空へ続く一対の大きな居住質量と、それらを結ぶ上部の都市室である。

主要地盤を標高600m・1,550m・3,000mに限定した。下部・中部では左右の地区が縦の大空洞に面する。上部では約3kmの高度に独立した都市室があり、前後の大きな開口から外へつながる。中央参照点の上下レイでは、床から屋根まで約729mの高さがある。これは部屋全体が同じ高さの直方体であるという意味ではない。

外壁の大開口は室内や地区を露出させるために切ったもので、窓の反復模様ではない。前面と背面では開口の高度と形を変えた。

### 長庭：厚い都市殻が囲む天空盆地

標高約1,500mに公共地盤を置き、その周囲を厚い都市殻・施設・居住支持体で囲む。大きな都市盆地と、その下の厚い都市基盤が一体になっている。

初期試作では開放的な外周フレームが巨大デッキに見えたため、外周を厚い都市殻に変更した。そのうえで少数の巨大公共開口を設けた。東の大施設、北の学術施設、斜都へ向かう公共結節の位置で、屋根と内部の壁を切り抜いた。施設の形を殻の上へ貼るだけで終わらせず、施設に合わせて主構造の空洞を変えている。

東側の大きな支持体も中空の都市構造であり、地上と天空盆地を結ぶ地区として扱った。住居・日常階の詳細はまだ入れていない。

### 斜都：共通地盤を覆う斜めの都市峡谷

厚い二つの側壁と斜めの大屋根が、上昇する都市空間を囲む。長庭と交差する部分では下側を開き、天空盆地の公共地盤が斜都の下へ続くようにした。上側の厚い部分には標高2,370mの地区を残す。

これは大きな斜行通路を一本置いた構成ではない。主殻の中に公共峡谷、高所地区、施設の屋根、交通の経路が入る。ただし、外観では太い斜架構造として読む余地も残っており、都市体としての独自性は十分ではない。

## 3. 地盤・大施設・交通の関係

| 主構造 | 都市地盤 | 数百m級施設・公共空間 | 主要なつながり |
|---|---|---|---|
| 天稜の居住壁・上部屋根 | 600／1550／3000m | 高所都市室、左右の公共地区 | 縦の公共空間と斜行交通が、地上・天空盆地・高所地区を結ぶ |
| 長庭の厚い都市殻 | 盆地1500m、東施設1540m | 東施設560×700×510m、北施設500×350×300m | 盆地の地盤が施設の入口へ続く。斜都側の公共街路は主屋根にも開口を設けた |
| 斜都の居住壁・大屋根 | 450／1550／2370mの主要地区 | 公共結節520×420×440m | 盆地の地盤を下側の峡谷へ取り込み、斜行交通で上の地区へ接続 |
| 三体の接合域 | 1550m／2370m | 公共門460×680×430m、天空交流施設420×500×350m | 大施設が高さの異なる地盤の接続を担う |

表の施設寸法は外形であり、その全体が無柱の空室という意味ではない。モデルには施設の床、厚い屋根、居住・交通コア、公共ギャラリーを入れた。

交通は都市地盤より一段小さい40〜55m級の包絡で表示した。斜行交通の内部車両や、住戸・日常階への全接続は未設計である。歩行用の床は水平を基本とし、高度差を移行地盤と交通で扱っている。完全な都市の運用性・避難・アクセシビリティを検証したモデルではない。

## 4. 実3Dを見て行った構成修正

1. **外周フレームの都市デッキ化を修正。** 長庭の外周を厚い居住殻へ置き換え、開口を少数の大きな公共門に絞った。
2. **閉じた盆地を修正。** 施設に向かう位置で内周の壁と屋根を切り、地盤をつなぐ広い入口を確保した。
3. **斜都による公共空間の閉塞を修正。** 斜都の下側の空洞を拡大し、長庭の公共地盤を取り込んだ。開口を塞いでいた包絡面も、実際の除去形状の境界に合わせて組み直した。
4. **施設と主屋根の食い込みを修正。** 施設の位置で長庭の主屋根を切り抜き、施設の床へ至る移行地盤を追加した。

いずれも、小建築・窓・発光装飾を増やす修正ではない。最初の試作は`geometry_r1.py`と`geometry_r1.json`に保存し、最終案とは分けた。

## 5. 実寸と主空洞

最終建築の外接寸法は、**東西4,937.81m × 南北3,535.53m × 高さ3,870.00m**。地下地盤70mを含み、地上最大標高は**3,800m**である。10kmの参照地面はこの外接寸法に含めない。

実際に主構造から削除した原形の開口は、天稜が最大幅1,870m・高さ2,780m、斜都が断面外接幅約2,596m・高さ1,960m、長庭の公共盆地が平面外接約1,944×1,271mである。

これらには他の都市体や公共施設が横断・接続する。組立後に、同寸法の空の直方体が残るという意味ではない。組立後の参照点から最初の境界までの実測値、測定方向、対象メッシュ名を`MEASUREMENTS.md`と`model_metrics.json`に収録した。空洞の寸法と建築の外接寸法を混同していない。

## 6. 旧モデルとの同条件比較

旧GLBを新しい背景プロセスへ読み込み、**外観5方向を描き直した**。旧ディレクトリの画像や制作記録へ書き戻していない。

両案とも1600×1200px、外観の平行投影幅7800m、同じカメラ位置・注視点、同じ太陽・ワールド照明、同じ都市体別の色と粗さで比較した。外観では室内補助照明を無効にした。カメラ値の一致は`verification.json`に記録した。

| 方向 | 旧案から明確に変わった点 | 残る不足 |
|---|---|---|
| 正面 | 高い居住門、斜めの都市峡谷、低く広い都市殻という主従がある | 巨大な門と斜架構造という既存形式の連想が残る |
| 斜視 | 床の積み重ねより、厚い三次元質量の奥行きが先に読める | 接合域の公共施設は主殻に隠れる部分がある |
| 側面 | 長庭の厚い殻と支持都市、斜都の長い空洞を分けて読める | 支持体と天空殻の接続がまだ単純で、造形の必然性が弱い |
| 俯瞰 | 連続した太い輪から、盆地・大屋根・斜めの軸の重なりへ変わった | 大屋根が盆地の一部を隠し、地上からの美しさほど強くない |
| 背面 | 天稜の異なる開口と厚い居住壁が主景になる | 高い門の輪郭自体は正面と共通で、背面の都市活動の表現が弱い |

内部画像は、各案で異なる公共地盤に立つため、同一カメラ位置での優劣比較にはしていない。新案は実際の床上1.7m、24〜28mmの透視投影を基本とした。床への距離はモデルのレイ計測で確認した。ドローン位置を歩行者視点と呼んでいない。

## 7. 美術自己評価

| 検証項目 | 判定 |
|---|---|
| 装飾を隠しても主建築として美しいか | **改善、合格未達。** 床の反復への依存はなくなったが、未来文明固有の強い造形にはまだ届かない |
| 単なる床の集合を脱したか | **成立。** 主殻・居住壁・大屋根・支持都市が輪郭を決める |
| 各都市体に異なる建築的性格があるか | **旧案より明確。** 縦の都市、水平の盆地、斜めの峡谷に分かれる |
| 高高度の独立した都市空間があるか | **低詳細で成立。** 3kmの高所都市室と、別高度の盆地・上部地区がある |
| 数百m級施設が主構造の一部か | **部分的に成立。** 屋根・内壁を施設に合わせて切り、地盤を接続した。接合部の外観表現は不足 |
| 都市生活が視覚的・空間的に連続するか | **未達。** 公共地盤と交通の骨格はあるが、空間が大きな室・広場の連続に留まる |
| 六方向に異なる魅力があるか | **改善、未達。** 主景の差は増えた。俯瞰と内部の構成密度に課題が残る |
| 旧案より建築全体の品質が改善したか | **主質量の整理と性格差は明確に改善。** ただし、それを圧倒的な建築美術の達成とは判定しない |

主な不合格要因は、(1) 門・斜架・舟形の地盤へ読み替わる既視感、(2) 高所都市室や盆地がまだ空の大空間として見えやすいこと、(3) 接合域を歩くときの次の公共空間への見通しが不十分なこと、(4) 俯瞰で大屋根の重なりが内部都市を隠すことである。

斜都の下部には細い三角形の残余質量もあり、構造・地区としての意味が未確定である。断面図にそのまま示し、低詳細段階の未達として残している。

**ここから細密化しても、今回の美術不足を解決したことにはならない。** 今回は低詳細モデル・比較証拠・評価を提出する段階で止める。正式採択・施工HOLDは維持する。

## 9. 再現手順

必要環境：Blender 5.2系、Python 3、Shapely 2.1。比較シートにはPillow、GLB読込確認にはtrimeshを使う。

1. `python geometry.py`：主質量・空洞・都市地盤を生成する。
2. `blender --background --factory-startup --disable-autoexec --threads 4 --python render.py -- --stage final`：新GLB、実測値、通常画像・解析画像を生成する。
3. `blender --background --factory-startup --disable-autoexec --threads 4 --python render.py -- --stage final --legacy`：参照用の旧GLBを同じ撮影条件で描く。
4. `python assemble.py`：比較図・閲覧ページ・確認記録を生成する。

`reference/`に旧GLBと旧カメラの読み取り用コピーを含めたため、元の研究ディレクトリを変更せず再現できる。旧制作コード・旧検証記録は元のディレクトリで保護している。

GLBの実ファイルを再読み込みし、形式・メッシュ・有限の外接寸法を確認する。水密化、全接合部の衝突検査、構造計算、施工QAは行わない。

## 10. 保護とMinecraftへの将来適性

旧研究ディレクトリ内の全ファイルについて、開始時と終了時のSHA-256を照合する。結果は`verification.json`、開始時の記録は`protected_legacy_hashes.json`に収録する。

正式HALO-9資産、sources、Minecraftワールド、GitHubは変更していない。Workへの新規切り替えは行っていない。

Minecraftでは、今回は多面体の居住壁、少数の主要地盤、大きな施設開口を使っているため、旧案の多数の薄い層より、基本構成を追いやすい。斜めの厚い殻、斜都と盆地の空洞共有、曲率のある都市盆地、交通と大施設の接続を保った離散化には技術研究が必要である。高度制限や施工容易性は今回の造形条件に入れていない。変換・水密化は未実施である。
