# J7-R14 — 多層居住世界の立体空間試験（研究用）

**2026-10-25 JST／Chat＋GitHub Actionsによる独立研究／Work・Computer Useなし／正式美術採択0／施工HOLD**

## 1. なぜR13の巨殻Cを詳細化しないのか

R13の最終C実モデルは約5.430×4.204×4.560km。BLEND/GLBの保存検証や2断面は成立したが、実レンダーでは巨大なアーチ状外郭・無地面・同形開口が主役。主形状はART REJECT。R13のまま窓・部屋・彫刻を追加することは否認する。

R14の狙いは**都市の数百m級の居住空間どうしが、空洞を隔てながらどのように立体的につながるか**という最小構造を検証すること。数kmの美しい主形状を作ったと先に宣言しない。

## 2. 新規局所3D試作の特徴

`build_lived_world_blender.py` はR13の原本BLEND/GLBを読み込まず、独立した研究座標で、次の6つの「都市世界」の露出地盤を一つのBlenderシーンに作る。

| 世界名 | 仮の底面高度 | めざす異質性 |
|---|---:|---|
| D01 Origin Cavern | 60m | 地下から届く公共大空間 |
| D02 Tide Garden | 90m | 水辺と緑を抱く内向き街 |
| D03 Overhang Commune | 245m | 外側と下側で生活が分かれる地区 |
| D04 Skyweave | 365m | 高高度の交差空間 |
| D05 Hanging Forest | 440m | 上方・下面につながる空中庭園 |
| D06 Vertical Harbor | 515m | 都市最上層に開く場所 |

各地区は**中央に開かれた巨大空間、複数高度の公開床、居住領域の立体的な支持要素**を持つ研究モデルとする。現代的な公会堂・図書館の外観を義務化しない。

- 各地区の中心には上方へ開く公共空間を確保し、外周の実地盤を7分割して露出させる。単一の巨大八角筒や空洞をくり抜いた無地モノリスとみなさない。
- 6地区の間には**7つの接続関係**を作り、高度差のある箇所には縦方向アクセスを想定した部材と高架連絡部材を明示。
- 一体化した巨大上屋は作らず、別高度の地区によって中央の都市空洞が囲まれる状態を研究する。
- 地区の実床の終端、アクセスの高低差、他地区と橋の幾何について証拠JSONを保存。

このプロトタイプはまだ現実の生活世界ではない。特に、現段階の「地区名称」「床」「縦アクセス部材」が存在するだけで各地区の内部の生活機能や真の歩行可能性が認証されたとは言えない。

## 3. 技術証拠と美術判断を分ける

Blender実行成功の条件：
- 研究用BLEND、対応GLB、同一シーン8実画像、基本形状QAの全保存
- GLBを空のBlenderへ再インポートし、メッシュ数の一致を検査
- 複数高さの地区とその連絡部材が実モデルにあることを記録
- 出力実体を研究用GitHubブランチへpushし、HEADから再取得できること

**美術合格には到底不足**。少なくとも正面・側面・背面・俯瞰・空洞内部・中高度地区から、抽象的な床と柱の模型ではなく、超文明固有の複数の居住世界であることが読めなければREJECT。

未検証：一体化した真正空洞体積、歩行メッシュ、縦アクセスの実運行、内部全詳細、力学的支持、10km都市正式座標、W0/H1〜H6/SB01〜SB16/HERO4との接続。

## 4. 特に厳しく見るべき失敗

**局所試作であっても、6個の同形地区を反復しただけ、巨大な部材・棚状床・アーチの反復、薄い浮遊床や岩に窓を付けただけなら美術REJECT。**

今回の有効な成果は、生活地区が他地区と空洞を介してどう接続するかの機械的に追跡可能な「構造的な仮説」である。

一度のGitHub Actions Blender作成は、R13の実Blender画面を見て造形を直すWorkの代わりにはならない。結果画像の美術審査をして次の修正ポイントを明示する。

## 5. Work / PCを占有しない方針

このR14ではローカルユーザーPCを直接操作しない。実BlenderはGitHub Actions内で稼働し、ユーザーのWindowsマウス・キーボードは完全に独立。

次の集中美術研究は、実際の画面を見ながらの深い造形が必要であればローカルWorkへ分ける。その際の標準方式は**Blender MCP / バックグラウンドBlender / Python API**であり、前面ウィンドウを操作占有するComputer Useは原則禁止。品質上の明確な優位がある場合のみ、**理由を説明して事前の許可を受ける**。

ユーザーの指定どおり、次回のローカルWorkを使用する場合は、**この工程で予告し、次の継続時にそのまま貼れるWork用プロンプトを出す。** 勝手にChatからモード切替画面を出さない。

## 6. 次工程の主要美術課題

仮に今回の地区・橋構造の技術QAが成功しても、AIは中央美術を自己採択できない。結果を見て、次は**1つの300〜1000m都市地区に、実生活空間の位置・上下移動・壁と床の変化・異なる環境を設け、全体の建築造形をそれらから生成**する方向へ移行する。

高い建築の一枚絵や読みにくいGLBのメッシュ数ではなく、人間視点と地区全景で「これは住まれる文明都市だ」と感じられることを優先する。

**J7-R15ではローカルWorkでこの美術課題を検証する予定**。後者（PC非占有）を原則とし、今回のR14はその直前の準備・実3D局所研究工程とする。
