# CELESTIAL HALO-9 / D29 — Topology + Visual Workbench

D28の実GLB 6視点編集環境に、**限定的な本物の開口・空洞のメッシュ再構築**を追加した隔離技術試験。
正式中央M247-Cのモデル、Minecraftワールド、main、都市Cの正式座標には一切書き込まない。

## Windowsでの起動

1回だけ `py -m pip install -r D29_requirements.txt` で依存関係を用意する（Python 3.13想定）。
以後 `D29_WINDOWS_ONECLICK.bat` をダブルクリックして `http://127.0.0.1:8769/` を開く。
ただし **Windows実機では未検証**。この環境ではLinuxのPython・FastAPI、ChromiumのTestClient通信代替で検証した。Windowsで自動起動することは未保証。

デモは直方体 `MASS_TEST`、保護される外部歩行路 `PUBLIC_APPROACH` の2メッシュ。
ボタン「1. 南入口を切断」→「2. 公共室を切断」→「3. 天窓を開ける」。各操作後に実GLBが再保存され、6方向の画像を再描画。右側の差分モードで変化を確認できる。「1手戻す」はブラシ・切断の最後の操作を戻す。再起動後の操作履歴も読み直す。

## 本質的な制限

- **任意形状への一般ブーリアンではない。** 既存の単一の軸平行直方体メッシュ（8頂点・12三角形）だけを、最大3個の軸平行直方体で切断する。D27の19メッシュやD28の球形デモにこの切断機能を適用することはできない。
- メッシュは箱の表面を色で隠したものではなく、内部表面も含めて新規三角形面として再構築する。保存済みGLBから個別メッシュ水密性を確認するが、部材同士の接合強度・自己交差一般・施工・耐荷重を認証しない。
- 外部から孤立した空洞を拒否する。接続は箱同士の3D体積の重なりに基づく限定検査で、入口幅・人間経路・避難経路を認証しない。
- 公共室の実例には簡易の水平な床面・開口と3D内部空間しかない。**利用目的・都市生活・設備・居住街区が存在しない**。美術品質の成功ではない。
- D28の頂点ブラシ機能は利用できるが、切断前に済ませるべき編集中のブラシがある場合は切断を拒否。新たな切断のために原本を上書きしない。
- 6視点の画像差分割合は美術スコアではない。

## 再現と検証

```powershell
py d29_verify.py
py d29_browser_check.py
py d29_render.py
```

`d29_verify.py` はGLBの作成・再読込、操作履歴の完全再現、Undo、異常入力拒否、公共メッシュ保持、243地点の床支持・729地点の空間干渉を保存GLBに対して別処理で確認する。
`d29_browser_check.py` はブラウザーの画面表示・UI操作を本物のChromiumで検証した。ただしこの実行環境ではブラウザーからlocalhostへのアクセスがブロックされるため、通信部分のみFastAPI TestClientを介した代替通信で検証。**Chromiumから直接localhost経由のフルスタック試験は未実施**。Pythonリクエストによるlocalhost HTTP応答は別途確認。
