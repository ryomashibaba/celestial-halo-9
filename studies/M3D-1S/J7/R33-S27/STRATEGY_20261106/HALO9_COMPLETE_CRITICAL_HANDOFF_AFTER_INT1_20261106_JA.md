### E2. 形状の制作方法を変える

- **R3/INT1不採用の直方体・巨大刃をテンプレートとして継ぎ足さない**。元研究BLENDは資料・比較・素材/照明/カメラとして参照できるが、外観の直接延命をしない。地形・カメラの利用も隔離コピーと出典の確認が前提。

- 手作業でのメッシュ編集・彫塑・カーブ・bmesh/geometry nodes等、実際に正しく制御できる技術を使う。**道具を新しく呼んだだけでは方法転換としない**。一括Python量産から、本物の実画像を見た後の大局的な形状修正へ移行する。GUI手彫り実行を偽らない。
- 高品質の建築美術参照は旧研究・画像などから活用できるが、画像生成を統合マスターの代用にしない。外注はしない。
- 初期からW0の崖と内海が中央の負空間を実際に制約するよう接続する。正式ワールド座標と誤認しない。

2. 少なくとも固定の**NAVE人間視点、H1人間視点、遠景/俯瞰**を同じBLENDから真正レンダー。3枚が暗転/壁内/遮蔽ならIMAGE INVALIDであり、ART PASSや改善なしの主張をしない。
3. 必ず**画像を開いて目視**し、(i) NAVEの巨大室の機能と深さ、(ii) H1の厚みを持った住める都市性、(iii) M247-Cの巨大母体/非対称双殻/斜裂の圧倒的主役性、(iv) W0との本質的関係、(v) 両尺度の**同じ建築思想**を明示的にART審査。
4. 不足があれば、**同じ研究コピーの同じ編集可能BLENDで**主質量・公共室の境界・街路・開口のうち根本原因を直接改造し、固定視点再レンダー。細部の追加と「カメラを都合よく変更」を美術改善の証拠にしない。
5. 集中的な**大きな修正1～2巡を目安**とし、改善の兆候がなければ凍結して別の制作手段へ切替。これは作業効率の目安でありユーザー承認済みの機械的閾値ではない。一次案が悪ければ厳格な資料参照のもと**質的に異なる1方向**を比較する余地を残し、単一案に無期限固執しない。
6. 主形状のART改善が確認できる場合のみ、側面・背面・地上入口・水際・重要内部等を含む7以上の正真正銘カメラを追加。遠景が強くても人間視点が駄目なら不採用、逆も同じ。
7. 美術的見込みが出てからFUNCTION（内部到達、住民動線、上下輸送、主要公共行先、床・壁干渉等）、寸法/統合座標検証、材質/光/装飾・30対象の詳細化へ。技術の最低限の安全・保存検証は常時必要だが、不合格形状のために大量の高コストQAを続けない。

### E4. ART審査で使う停止/改善判断

| 観察状態 | 判定・次行動 |
|---|---|
| 黒画像・遮蔽・壁/床内のカメラ | **IMAGE INVALID**。実形状/配置の原因を調査。描画署名が通ってもART審査不可 |
| NAVE/H1は良いが遠景が箱・塔・小ビル群 | **ART REJECT**。住宅/窓増加停止。巨大母体/斜裂と住区の関係を主修正 |
| 遠景は壮大だが公共室が空洞と橋だけ | **ART REJECT**。殻や発光の追加停止。室用途と生活都市を造形し直す |
| 3視点の形は改善、内部アクセス未検証 | **ART候補研究／FUNCTION UNKNOWN**。正式採択せずアクセス検証 |
| 造形が3視点で向上、全景/側面は未審査 | **PARTIAL ART IMPROVEMENT**。大規模ディテール化前に全周・室内検証 |
| 技術PASSだが総合美術劣化 | **TECH PASS / ART REJECT**。隔離保存・形状延命停止 |
| 複数の視点と用途が高品質で揃う | **ART候補、独立審査待ち**。それでも自動で正式採用・30件完成としない |

機械的な数値・メッシュ数をART合格閾値として捏造しない。比較は建築全体の美術的因果を説明して判定。**結果が不明なら不明、改善根拠が見えないなら不合格**。

### E5. 10km統合マスターへの復帰（先送りしない）

代表断面の成功は「30件完成」ではない。良い造形思想が生まれた時点で、W0地形の連続性・H1以外の居住地区・V1～V3・三都市軸・SB施設と相互調整する**共通研究座標の編集可能マスター**へ接続する。正式世界座標は別途正本照合/認証。その後、全地区・全16施設・全ての普通建物外観を詳細化する。中央だけに開発資源を閉じ込めることも禁止。

## F. 作業効率・ユーザー操作の徹底削減

- **ユーザー操作0回を通常経路**とする。GitHubの読取り、批評、プログラム・同一研究BLEND編集、CI、短いART記録、保存を可能な限りまとめて行う。新チャット移行は本書リンクを**短い一文で貼るだけ**。
- ローカルPCでしか不可能な形態編集が必要なとき、ユーザーに何度も命令/スクショ/ZIPを送らせず、非画面占有CPU利用・原本からの隔離clone・リソースガードを使う**安全な1クリック実行**を優先。ただし**ローカルへの接続・PCの遠隔操作権限を仮定しない**。勝手にファイル操作・インストールを始めない。Work/Computer Useの開始はその都度承認。
- GitHub Actions上のBlenderが使用できるなら、無意味な並列ジョブ/サイズの大きい何層ものbase64配布を避け、平文Python + 1つの再現性あるワークフローで**実制作→最少の技術確認→実画像→ART審査→隔離保存**。Artifactsの7日保持に依存せず、編集可能BLENDと主要比較画像は研究枝で保存。ただし研究枝Gitの容量・無料枠も無制限と仮定しない。
- CI FAIL、実行中、ブランチ保存のみ、ローカル未接続を「完成」と報告しない。別Blenderプロセス再読込/PNGは技術の真実性を証明し、ARTの判断は直接画像から。
- 作業報告は1回に**何を実際に変更したか・何が良く/悪くなったか・TECH/FUNCTION/ART/完成判定・保存先/HEAD・次の具体制作**だけ。計画やQAの大量報告を主成果としない。
- 課金に関しては、**有料API・有料外注・有料Workを使わない**。GitHub無料枠等の残量・料金は実際のアカウント請求画面を見なければ絶対保証できないため「追加課金を発生させた証拠なし」と「請求額0円を監査済み」を混同しない。

## G. 計画への反論・批判的再検討（再点検済み）

1. **「内部と外形を同時に作る」だけでは抽象的** → 造形の具体的な同時条件（NAVE用途3／H1居住・上下街路／M247双殻＋斜裂／W0地形・水際）と早期3視点の相互因果を明記し、別々に後付けする逃げ道を塞ぐ。
2. **1候補へ集中しすぎると外れに固執する** → 根本修正を1～2巡、目に見える改善がないときは止め、手段/構成を質的に変更する比較方向を許す。反面、無計画な10案量産はしない。
3. **3視点だけでは実際の全周立体美術を保証できない** → 初手の3視点は安価な棄却用、良い候補のみ正面/側面/背面/水際/室内等に拡張。画像由来の見せかけ合格を防ぐ。
4. **背景BlenderのPython編集が手法の限界では** → その可能性は高い。成功実績は「技術的な実行経路」に限定し、ARTが改善しないなら実際の対話的Blender編集や他の無料実行環境を安全条件で検討。ただしツール名変更で美術成功と偽らない。
5. **中央代表断面だけでは約10km全域目標から逸れる** → 代表断面は品質を確立する中間工程であり、正式30件完成条件は変更せず、W0・都市軸・H地区の広域関係を最初からモデルに含める。
6. **完璧な制作計画なら実作業は必ず成功するか** → いいえ。芸術品質を100%保証することは不可能。今確実にできるのは**失敗が美術的に早く判明する仕組みと、固定方針を破らず学習できる開発手順**を採用すること。
7. **ユーザー作業0回を絶対視すると行動が止まる** → Chat/GitHubで可能な範囲まで実行したうえで、残る唯一のローカル操作が不可避なら1クリックの安全な単一パッケージだけ用意。不要な入力・追認・待機を求めない。
8. **「さらに次の工程」と言われても研究の境界を誤る恐れ** → 本書と研究枝を明示し、他プロジェクトの作業へ飛ばない。CELESTIAL HALO-9の固定ART-FIRST、M247-C研究、CITY MASTER 3D FIRSTを自動継承。ユーザーの明示的な方針変更がない限り新企画と解釈しない。
