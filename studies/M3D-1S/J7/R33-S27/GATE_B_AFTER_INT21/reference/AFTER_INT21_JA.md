## 4. 批判的に考え直した根本問題

**事実：** INT1〜21でBlender/Sculpt/X11/MCP/独立検証の能力は明らかに増えた。しかしART正式採用は0件。

**最も整合的な原因仮説：**
1. 制作の主導権が「何を本当に建てたいか」でなく「PythonやBlenderで簡単に生成できる形」に移っていた。箱→刃→卵→穴→板→別の卵の移動へと反復。
2. NAVE巨大公開室・H1高高度居住街区・斜裂天脊・W0水際という**同じ思想の建築**を決める前に外殻やオブジェクト名が増えた。リフト名、駅名、通路の端点、穴の数は利用可能な公共施設の証拠ではない。
3. INT21でも**不採用の巨大卵を再配置して延命**した。これはINT16〜17の反省と整合しない。少し開けた俯瞰をART前進の中心結果とするべきでない。
4. 「GUI/MCPを使用」や「before/after画像を取得」は、**画像の芸術的判断に応じた具体的な再造形の反復**を意味しない。INT21も1回の前画像に基づく計画済み3変換→後画像という限定技術実証。真の視覚対話的ART制作はまだ未実証。
5. 事後のCIや独立QAは強力だが、芸術不合格を多数のTECHテストで覆せない。工程名、PR、JSON、レンダー、コミットの量で制作進展を誤認した。
6. 過去のCI問題（X11座標ずれ、メッシュの低頂点密度、Blender互換性、ファイル名/PIL保存間違い、Ubuntu依存、MCP画面コンテキスト、重複Actions）を解消したのは良いが、**これ自体を「ART制作の次工程」として何十回も繰り返した効率の悪さ**を反省する。
7. 機能はARTと別だが無視は禁物。INT13の急勾配、INT15の一部未切削Boolean、INT21の移動後の接続不明は「端点がある＝本当に歩ける」ではない。
8. 固定E11は最低限の**前後比較**には有効だが、独立した新設計には正面・側面・背面・内部・W0地形との統合画像も必要。追加の綺麗なカメラだけで固定画像の問題を隠すのは禁止。
9. GitHubのActionsランナー・外部MCPに関して個人の実請求・全将来コストは不明。毎回Blenderの大型再ダウンロードと長時間レンダーを繰り返すのは効率面の負債。
10. ただしアーチ・曲面・殻・リング等のカテゴリ自体を永久禁止するのも誤り。**不合格の具体的メッシュを捨て、採用された美術思想から新たに造形する**のが正解。

以上の「原因」は断定的に科学実証されたものではなく、21工程の実画像失敗に整合する制作判断の仮説。成功率を数字で捏造しない。

- **毎回の数字のためにINTを増やさない。** 作品に本質的な主形状の変更がないなら新しい番号を作らない。レポート/QA/画像生成だけの「制作工程」を増やさない。

- **報告の固定欄：** SOURCE / TECH / IMAGE_VALID / ART / FUNCTION / FORMAL_ADOPTION / COMPLETION / CONSTRUCTION / COST_AUDIT。エビデンスと事実を分け、わからなければUNKNOWN。
