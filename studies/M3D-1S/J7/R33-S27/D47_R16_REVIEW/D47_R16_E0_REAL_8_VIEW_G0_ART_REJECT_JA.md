# CELESTIAL HALO-9 — R16 E0 二重中空都市曲面・真正Blender 8視点の実画像美術判定

**基準日 2026-10-30 JST。R16 E0：SOURCE TECH限定PASS／ART REJECT／現3Dの詳細化停止／正式美術採択0／Minecraft施工HOLD。**

## 1. ここまでの全体方針と今回の変更点

本工程は恒久憲章`main/docs/policy/PROJECT_CONSTITUTION.md`・`CITY_MASTER_3D_STANDARD.md`のART-FIRST／CITY MASTER 3D FIRSTに従う。R1〜R13の大量の箱・棚・2枚板・柱群・パビリオン、R14のGUI局所操作治具、R15 D系統の季節展開樹冠（現形状ART REJECT）を確認したうえで、それらを改装せず独立新作の造形初期G0に限定した。

以前の「単純箱の反復」ではなく、左右の不均等な高さ・傾き・奥行きを持つ曲面の全厚中空都市母体を、少数の**作者指定の異なる断面制御点**から実際のBlenderメッシュとして生成。外表皮と内表皮、連続した縁・先端の接合、壁の実開口、6つの内側公共床、共通地上到着地盤を同一ネイティブBLENDへ保存。外形だけの参照画像やImageGen画像ではない。

**重要な透明性：制作はBlender 4.5.15のバッチPythonであり、R14の本物のGUI編集は本R16モデル自体に対して行っていない。** 直接GUIを動かしたと表現しない。形状は編集可能で各メッシュに後編集用シェイプキーを保存。

## 2. 本物の技術検証範囲と限界

GitHub Actions [R16初回CI #41044309258](https://github.com/ryomashibaba/celestial-halo-9/actions/runs/41044309258) では、真正3D、8 PNGレンダー、独立再読込とメッシュ形状の検査はPASSしたが、**研究ブランチへZIPをpushする最後の工程だけがremote ref競合でFAIL**。審査契約ファイルの同時コミットでリモートHEADが更新され、pushの期待するHEADが古かったため。形状・画像・独立QAの問題ではないが、CI全体をSUCCESSと表現しない。後続の保存経路で非強制pushを修正して再実行しなければ研究アーカイブ保存完了と呼ばない。

## 4. 最終ARTと停止判断

**R16 E0：SOURCE TECH限定PASS／G0 ART REJECT。**

R16の初期形状を後付け窓・電飾・小住宅・公共床の大量追加で延命しない。両側の寸法や制御点を少しずつ変えて第三、第四の巨大花瓶を作る工程も停止。本人が望む「圧倒的な美しさを持つ10km超未来文明都市」としては根本的なイメージ・都市街区・実居住密度・空洞形成原理に欠落がある。

**今回増えたこと**：旧来の巨大板／箱の反復から離れ、厚みのある連続非対称曲面を一つの編集可能3Dシーンとして形成でき、6つの実ギャラリー床を内側に配置する基盤ができた。
**今回増えなかったこと**：その曲面が美しい未来都市であるという証拠、街区の住居や公共空間が真に存在すること、地上・高所を行き来できること。Tech数値を最上位成果に見せない。

## 5. R17に必要な制作方法の根本変更

R1〜R16で、**下地となる単一の「大きな基本形」から外形と生活を導く作り方**は再びREJECTとなった。問題は曲面の計算式を難しくすれば解決することでも、画像枚数をさらに増やすことでもない。

R17の入場条件は次の通り。

1. **街の実景・公共空洞・高高度市街地の建築空間を、ひとつの巨大表皮を作る前に**芸術的な具体的なシーンとして設計する。ただしR13のような抽象柱とパビリオン群から作るのも禁止。現実に存在する都市の厚い立体断面、地形、緊密な公共室・文化地区・交通を一つの建築思想へ統合する。
2. いきなり数km級の全体を制作せず、**100〜400m級の1つの内外が成立した編集可能な実建築断面**を先に完成させる。良い作品になった場合だけ広大な超未来の造形へ発展させる。R13で失敗した無数の別パビリオンは作らない。
3. 3D画面の中で**人間がそこへ行けるか・空洞の内部から公共活動が見えるか・夜に照明を消しても良い輪郭か**を必須の美術基準とする。低所／高所の内部が見えなければG0 STOP。
4. 巨大母体の形式自体は禁止しない。大アーチ・リング・曲面・二重殻はいずれも形の良し悪しで判断し、一律禁止する方針を採用しない。失敗したのは今回の比例・空洞・居住都市の実体である。
5. 実画像を見た部位指定のGUI編集を行うなら、今回のBLENDの目先の救済にせず、**独自の新しい実3D原本**に対して形を実際に見ながら変形し、同じカメラで改善を比較する。
6. WorkやユーザーPC GUIを利用する場合には従来どおり事前明示承認制。Chat/GitHub Actionsを基本とし、新規外注も不要。
