## 2. D23〜D27からの教訓

過去の実GLB研究は編集・QA自体が技術的に進歩したにもかかわらず、美術的に平凡な壁・箱・屋根・床・塊へ収束した。特にD25では室内を変更しても遠景はほぼ変わらず、D26/27では変位で遠景を大きく変えても美術が向上しなかった。そこで**D28では次の新しい未実証能力を実装対象とした**：実際の保存GLBを多視点で観察 → 画像をクリックして表面の頂点を選択 → 局所的な頂点変位 → 6方向の実GLBレンダーを再作成 → 編集前／編集後／赤色差分を見比べる → UndoやJSON編集履歴で戻せる。

これは建築デザインを提出した工程ではなく、**建築美術を改善するための制作環境を得る工程**である。

## 3. 実装内容

**主コード：** `d28_visual_workbench.py` — FastAPIとVTKのローカルWeb UI。WebGLや外部画像サーバーに依存せず、保存済みGLBからVTKが6視点のPNGを描画する。VTK `vtkCellPicker` の実ピック座標から幾何オブジェクトと頂点IDを決定する。ブラシ半径内の頂点へsmoothstep重みで移動量を適用し、元GLBから全履歴を順に再構築して別ファイルへエクスポートする。

- 画面内に南・北・東・西・俯瞰・斜視の6カメラを表示。
- 実画像のクリックにより選択したメッシュ名・頂点ID・3D座標が表示される。
- 編集前／編集後／画素差分をボタンで切替。画像差分は画素RGBチャネル最大差が20超の割合。**美術の点数ではない**。
- XYZ変位・半径指定・1手Undo・GLB/JSONダウンロード。
- ローカルの任意の対応GLBを画面から読み込み。16MB/120メッシュ/35万三角形などの初期ガード付き。
- 元GLBを変更せず、ワークスペース内に独立コピーを保存。基準SHAがずれた履歴を拒否。
- D27由来の研究用公共経路`civic_spine`と広場`civic_plaza`は、UI/API操作でも編集履歴を書換えた場合でも保護。
- モデル変形は元の三角形インデックスを保持。法規・構造・接合・空洞と人間の連続通行は未認証。

**起動：** Windowsの場合、Python 3.13で `py -m pip install -r D28_requirements.txt` を一度行い、その後 `D28_WINDOWS_ONECLICK.bat` を起動。自動で `http://127.0.0.1:8768/` を開き、内蔵の中立試験モデルが表示される。手元のGLBは右側のファイル入力から読み込み可能。追加アカウント、有料サービス、外注は不要。ユーザーの実Windows PC上での動作は未確認。

## 4. 実際に確認できた証拠

中立の技術用実GLB（2メッシュ計2,560三角形、各642頂点）に対し、実6視点をVTKで出力。南視点の画面クリック位置(0.30,0.53)で実表面`NEUTRAL_A`頂点626を選択。半径220m・変位(+35,0,+20)mを適用。保存GLBのSHA256はBASE `78f01f6ff4ed2de539d809188048eefa43c305245bd669927f281c61aa98df4b`、EDIT `0e2ad91911cad94171d0e9add3e32a8813e0a6b5517e60c0c6461c345cb03656`。6視点画像の画素変化は南1.882%、北1.994%、東1.076%、西3.530%、俯瞰1.249%、斜視1.479%。全視点で差分が実在する。未選択の`NEUTRAL_B`頂点と両メッシュの三角形接続は不変。

**独立レシピ再実行：** 初期GLBと保存したJSON操作のみを別処理で読み込み、EDITとバイト単位で一致。Undo後は基準GLBの元バイト列に戻る。

**負例：** ゼロ半径、古い編集リビジョン、加工した履歴SHA、原本改変、公共経路の保護メッシュ指定を拒否。D27保存GLB（19メッシュ、3,768三角形）を別ワークスペースで読み込み、保護された2つのメッシュを操作できないことを確認。D27元GLBはSHA不変。

**ブラウザー実行：** Chromiumで6枚の実レンダーを表示し、クリック・編集・Undo・差分切替をテスト。現実行環境ではlocalhostのChromium直接ナビゲーションが管理ポリシーで拒否されるため、ブラウザー側の通信だけをTestClientブリッジで置き換え、同じFastAPI処理を呼んだ。**このテストは直結ネットワークのブラウザー端末確認を意味しない。** ローカルAPIのHTTP疎通は別途curlで確認済み。

## 6. D29の合理的な次工程

D29で単純な巨大壁・箱・球の新規美術を量産してはならない。まず、D28環境で **(a) 外殻と内部公共空間の同時編集を可能にする位相・空洞編集、(b) 編集影響を伴う多層都市／高架交通の連動、(c) 人間視点で公共目的地が現れる6視点以上の美術レビュー**を一組の実3D試験として結びつける。ただしD28のブラシだけでは不可能なので、Blenderネイティブ編集等の別手段が明確に有利ならWorkの事前明示承認を求める。実際の美術案を制作する段階では、中央・周辺・W0を同時に考え、受け入れられる遠景・内部空間がなければ詳細化しない。
