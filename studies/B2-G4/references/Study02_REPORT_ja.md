# 《断海宮》第二構成研究 — 交湾大陸

2026-10-22 / CELESTIAL HALO-9 / Chat B / ART-FIRST

**結論：研究を続ける主構成として《交湾大陸》を選ぶ。船体状の上下二質量と、支持体に偏った背面は解消できた。一方、現行3Dの美術的完成は証明できていない。正式美術採択・施工はHOLD。細密化・高度な水表現へは進まない。**

## 2. 根本的に異なる二つの構成案

ここでの「案Ⅰ／案Ⅱ」は形態案。「状態A／状態B」は海の表示状態を指す。

### 案Ⅰ《三湾連都》

三つの巨大な都市地盤が、それぞれ異なる高さと向きから海を囲む。低層の生活都市、中層の公共都市、高層の学術都市を、厚い基部と数百m級の接続地盤で結ぶ。

海は三つの湾へ入り込み、各都市岸が異なる海の断面を持つ。前回の二枚の船体から、複数方向の街区と海岸を持つ構成へ移る案である。

長所は、地盤ごとに大きな都市空間を確保しやすいこと。弱点は、三つの塔・支持体・接続部へ形が分解されやすく、一つの都市大陸としての圧倒的な質量が弱まる懸念である。前回の背面の問題を、三方向へ拡張してしまう可能性がある。

**今回は採らない。概略図まで。実3Dによる不合格判定ではなく、構成原理の段階での選抜判断である。**

### 案Ⅱ《交湾大陸》

一つの厚い都市大陸を、向きと標高の異なる二つの巨大空洞が貫く。正面には低い海の湾、側面と背面には高い都市の湾をつくり、その交差部を曲がりながら上昇する海が通過する。

都市は海の周囲に貼り付く小さな建物群ではなく、主質量の一部を大きく後退させた水平な都市地盤に成立する。正面に海を見る都市、背面に空と海を横から見る都市、上部に実際の空へ開く都市がある。

長所は、外観・空洞・都市地盤を一つの大きな立体として設計できること。弱点は、都市生活の厚みが不足すると「大きな穴を開けた彫刻」になってしまうこと。

**こちらを選抜。三次元の奥行きと、背面にも都市の正面をつくる可能性を優先した。**

| 比較軸 | 案Ⅰ 三湾連都 | 案Ⅱ 交湾大陸 |

| 主質量の原理 | 複数の都市質量を接続 | 一つの主質量を都市湾で貫通 |
| 海の配置 | 各質量間の複数の湾 | 向きの違う二湾を結ぶ屈曲した水体 |
| 都市の階層 | 各質量に別の都市 | 主質量の厚みに異なる標高の都市 |
| 背面の可能性 | 接続構造が支配する恐れ | 高層都市の主正面にできる |
| 最も大きい造形リスク | 塔群と橋の組み合わせになる | 穴のある外殻・段状の塔に還元される |
| 制作範囲 | 平面・断面の概略図 | 概略図＋実3D1案 |

## 3. 選抜案の主質量と主要空洞

### 3.1 一つの巨大な都市大陸

基部から高部まで連続する、幅約4.93km、奥行約4.00km、高さ4.66kmの主質量をつくった。都市地盤・施設を含む全体は幅約5.12km、奥行約4.17km。

主質量は、下部から上部へ段状に後退しながら、その中心も横へ移る。正面の巨大な空洞と、側面の高い空洞を同じ方向へ並べないため、見る向きによって質量の重なり方が変わる。

メッシュの連結性を調べ、主質量は実際に一つの連結成分であることを確認した。外観上だけで複数の独立体を連続していると説明していない。ただし、メッシュの連結性は構造安全性の証明ではない。

### 3.2 正面の《海都市湾》

低い位置から立ち上がる、最大幅約3.05km、高さ約2.62kmの巨大な空洞。床側には広い水平領域を確保し、上部を大きなヴォールト状の主質量が覆う。

前回のように斜面全体を都市床にせず、空洞の下部を水平な公共都市に変えた。ここから中層の都市地盤と海の下面を見上げる。

### 3.3 側面・背面の《高層都市湾》

前方の湾に対して約90度向きの異なる、高度2.1kmから開く都市空洞。幅約2.22km、高さ約1.63kmの切削領域を持ち、奥行き方向は主建築を横断する。

背面は支持体の裏側ではなく、大学、住宅、中庭、公共庭園が湾に面する都市の正面になる。低い海都市湾とは、視線・都市の標高・海の見え方が異なる。

### 3.4 頂部の《空庭》

頂部には、上方の実際の空へ開く大きな切り込みをつくる。高層都市湾と光・視線を結び、頭頂部を平らな巨大な蓋にしない。

現状ではこの切り込みが大きく、頂部がC字状の輪郭として強く読まれる。この輪郭をそのまま最終形態として採択してはいない。

## 6. 同一モデルのA/B比較

新しい実3Dシーンは1つ。建築32オブジェクト、海1オブジェクト。

- A：海コレクションを表示。
- B：同じシーンで海コレクションだけを非表示。
- 主建築、施設、庭園、カメラ、背景、光源、露出、画角は変更しない。
- 8視点すべてでA/Bを撮影。計16枚。
- GLBはA/Bの二つ。Aだけに海の1ノードが追加される。

元メッシュの頂点・面・変換・交通曲線の点列から建築ハッシュを作成し、各レンダリング時に同一性を検査した。GLBについても共有メッシュの属性・面インデックス・ノード変換が一致することを別途照合した。

海は半透明の検証用立体であり、流体・波・魚・泡・体積吸収・高度な反射やコースティクスは使っていない。水を消したことで透過や影が変わるのは、水の表示を変えた結果である。照明を調整してBを魅力的または不利にしていない。

## 8. 海なしでも残る美しさと、海との必然性

**海なしでも残るもの**は、主質量の非対称な輪郭、交差する二つの都市湾、厚いヴォールトの下面、前後にずれた都市地盤、中庭地区である。Bの背面にも大学・居住地区が残るため、前回のように支持構造だけへ戻ることはない。

海ありでは、二つの湾が、同じ厚い水体を異なる高さ・方向から見る都市世界になる。低層では海が上部都市とともに頭上へ現れ、高層では海の側面が公共地盤の近くに来る。空洞の中の距離と視線が変わる。

ただし、「海なしでも彫刻として成立する」ことを合格の根拠にはしない。逆に、BがAより弱く見えることだけで不合格にもしない。

今回の重要な未解決点は、**海がこの外形でなければならない理由を、遠景の造形として十分に伝えきれていないこと**である。海の露出が斜めの帯へ集中し、外形の一部は他の大施設にも転用できそうに見える。海によって生まれた独創的な輪郭としての説得力は、まだ強化が必要。

**今回の成果は、採択可能な完成形ではなく、前回より三次元の都市構成を持った第二研究モデルである。**

ここで低詳細制作を停止する。窓や小建物を大量に置く、高精度な海に置き換える、魚や発光で画面を埋める、といった工程には進まない。次の研究では、大きな都市地盤の形と海岸線の関係、主質量の反復、歩行者の視線の抜けを修正すべきである。

## 10. 実現可能性とMinecraftの技術評価

美術上の判断と分ける。以下の技術的な制約を、初期形態の禁止条件として使っていない。

### 今回実現したこと

実3Dメッシュ、主質量の二方向の大空洞、中庭と大きな開口、水平な都市地盤、厚みを持つ海のメッシュ、同一カメラのA/B、GLBとBlenderシーン、再制作コード。

### 仮想文明の前提

空中で屈曲した海を保持すること、巨大な開口・張り出しを持つ都市大陸の支持、海と居住空間の環境分離。構造安全性・圧力・海洋循環・生態・防災・交通容量を実証したものではない。

### Minecraftの切り分け

| 要素 | 区分 | 限界・前提 |
|---|---|---|
| 主質量の輪郭、二つの空洞、水平地盤、中庭・施設の相対配置 | 静的形状として忠実に翻訳できる対象 | 十分なボクセル解像度とワールド範囲が前提。通常ワールドに原寸で施工可能という意味ではない |
| 曲面・斜面・大きな庇の断面 | ブロックの段状近似 | 小さく縮めすぎると、質量の厚み、海岸と都市の距離、公共空洞の大きさが変わる |
| 庭園・広場・公共施設の用途 | ゲーム内空間として表現可能 | 実際の移動経路や設備の設計は今回の低詳細モデルに含まれない |
| 海の静的な外形 | 半透明材や独自モデルによる近似対象 | 通常の水と同じ泳げる空間ではない。透明材の重なり・描画順・遠景の濁りは別途検証 |
| 露出した側面を持ち、空中で曲がる自由水体 | 通常のMinecraft水ではそのまま成立させにくい | 水の拡散と更新に対する保持の仕組みが必要。透明な保持壁は水槽的に見える問題を再導入する |
| 非標準の水保持・海洋描画・実際の遊泳 | 特殊技術が必要な検討対象 | 対象エディション・バージョン・Mod等の可否を確認してから別研究。今回は実装しない |
| 原寸高さ4,660m | 標準的な垂直範囲では困難 | Java 1.18で導入された384層のOverworldを基準にすると原寸は収まらない。高さだけを合わせる約1:13縮小は目安であり、美術や生活尺度を忠実に保存する解決ではない |

通常水が周囲の空気ブロックへ広がる性質、Javaの表示エンティティが視覚表現用の変換を持つことなどは一次資料を参照した。表示エンティティ等を使えばこの海がそのまま実装できるとは主張しない。対象環境を調べていないため、導入技術と性能の可否は未判定。

- `07_HIGH_CITY`：高層の歩行者視点。A/B。
- `08_INTERIOR_WIDE_AUX`：超広角補助。主要評価には用いない。
- `concepts_comparison.png`：二つの構成案の平面・断面図。
- `baseline_vs_studyII.jpg`：旧GLBを今回と同じカメラ・地面・照明で再撮影した新旧比較。
- `six_views_A.jpg` / `AB_comparison.jpg` / `hero_AB.jpg`：実レンダリング画像の一覧。
- `review.html`：ネットワーク不要の画像比較ページ。
- `comparison_manifest.json`：カメラ、寸法、床高検査、建築ハッシュ。
- `baseline_checksums.json`：旧原本の保護記録。
- `baseline_camera_manifest.json`：旧GLBを今回の斜視カメラで再撮影した記録。
- `geometry_audit.json`：主質量の連結成分、形状の体積等。
- `verification.json`：A/B出力、カメラ、原本保護の照合結果。

新旧モデルは同一カメラで撮影したが、旧モデルの材質はGLBのインポート変換を含む。新旧間で材質の完全な同一性を主張しない。新モデル自身のA/Bでは材質も共通である。

PowerShellで`reproduce.ps1`を実行すると、二案の概略図、新モデルのシーン・GLB・全画像、旧GLB比較、監査、比較ページ、ZIPを再制作する。Blenderの場所は引数で変更できる。PythonはPillowを使用する。外部アセットやネットワークは不要。

```powershell
.\reproduce.ps1 -BlenderPath 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe'
```

ZIPには前回原本の読み取り用コピーを`references/`に含めた。元ファイルが同じ相対位置に存在しない場合も、コピーから比較を再現できる。参照コピーを編集する工程はない。
