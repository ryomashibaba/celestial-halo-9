# 《断海宮》巨大海洋都市・美術成立性検証 01

2026-10-22 / CELESTIAL HALO-9 / Chat B / ART-FIRST

**判定：構成原理は部分成立。圧倒的な巨大主役建築としての美術的完成は、今回の3Dでは証明できていない。正式美術採択・施工はHOLD。**

水の描写を強化して不足を覆う段階には進まない。次に必要なのは主構成の修正であり、魚・窓・波・高精度水面の追加ではない。

## 1. 制作物と検証範囲

共通の実3DシーンをBlender 5.2.1で制作した。建築64オブジェクト、海1オブジェクトの低詳細モデル。独自のメッシュと単純な都市施設のみを用い、他の研究案、既存作品、外部3Dアセットは参照していない。

- `dankaikyu_master.blend`：共通シーン。`02_SEA_TOGGLE_ONLY`コレクションで海の表示を切り替える。
- `dankaikyu_A.glb`：主建築＋海。背景、都市範囲線、光源、カメラは含めない。
- `dankaikyu_B.glb`：同じ主建築のみ。
- `01_FRONT`〜`06_INTERIOR`：正面・斜視・側面・俯瞰・背面・内部。各A/B、計12枚。
- `07_TERRACE_EYE`：公共段丘の床面から約1.7mの補助視点。A/B、計2枚。
- `review.html`：オフラインの画像比較ページ。左右キーでも視点を切り替えられる。
- `AB_comparison.jpg`：正面・斜視・内部の比較一覧。`six_views_A.jpg`：海あり6視点一覧。
- `comparison_manifest.json`：固定カメラ、境界寸法、画像ごとの建築ハッシュ。
- `verification.json`：画像の存在、A/Bの出力同一性の検査結果。
- `build_scene.py`：主シーン・GLB・全画像の再制作。`make_review.py`：実レンダリング画像の一覧化と照合。

水は均一な半透明の色付き立体である。波・流体・体積吸収・コースティクス・魚・海面の高精度反射は実装していない。外観の色は、白系の建築、青緑の水、庭園面、控えめな交通経路表示のみで構成する。画像はレンダリング後に描き足していない。

## 2. 海あり／海なしの同一性

A/Bでは水コレクションの`hide_render`と`hide_viewport`だけを変更する。主建築の位置・形状・材料、同一視点のカメラ、背景、照明、露出、画角、解像度は変更しない。

建築メッシュの頂点・面・変換と、交通曲線の点列からSHA-256を生成し、各画像を出力する直前・直後に一致を検査した。GLBについても、共有ノードの変換およびメッシュ属性・面インデックスの同一性を別途照合する。Aだけに追加されるノードは`SEA / inclined ocean volume`の1個。

海を取り除いたBでも、海のためにつくられた空洞、庇、施設配置は残っている。Bが別用途に最適化された設計でないことは、比較の意図に含まれる。

カメラの調整は各A/Bに同時適用した。最終の側面・俯瞰は全景が画面内に収まる広さとし、補助の歩行者視点は施設の遮蔽を確認して再撮影した。歩行者視点に残る大きな壁の遮蔽も、街路構成の課題として扱う。異なるカメラの画像をA/Bとして組み合わせていない。

## 3. 今回、海によって建築が変わった部分

### 3.1 主質量と輪郭

斜めに上昇する海の下縁に沿って、下部都市大陸がせり上がる。その上方には、海の上縁を追う深い下面を持った上部都市大陸が掛かる。背面の三つの厚い支持体が、両者をつなぐ。

この海を通常の水平な地上池に置き換えるなら、約1.5km級の連続した断層空間や、異なる標高の施設を同じ水体に面させる構成は必要なくなる。海の配置は建築の主断面を変えている。

ただし、今回の上下質量は全体として同じ傾きに従いすぎている。遠景では「海により裂けた都市大陸」から「二枚の大きな斜板」へ還元される余地がある。主質量を生む因果関係と、造形の独創性の完成は分けて評価する。

### 3.2 巨大公共空間

海を奥に、都市段丘を手前に置き、両者の間に数百m〜約1km規模の奥行きを確保した。大きな庇の下面と海の側面を、一つの内部景観として見ることができる。海なしでもその空洞と深い日陰が残るため、公共空間の大枠は青色だけに依存しない。

一方で、その空間の床が斜面として連続しすぎている。水平な公共段丘は配置したが、段丘同士を日常の街路として歩く関係や、大きな広場から小さな居場所へ移る関係は十分につくれていない。

### 3.3 数百m級施設

下部には海洋市民院、中央には研究院、上部下面には深層図書館、上部前面には庭園を伴う都市地区を配置した。異なる高さの施設が同じ海を共有する関係は立体化できた。

施設は用途・規模を持つ設計上のボリュームであり、室内が完成した建物ではない。外形はまだ箱の反復が強い。公共施設が主構造を変形させるほどの相互関係は未完成で、現状は「主質量に取り付いた施設」にも見える。

### 3.4 光と海の深さ

Aでは、上部の大きな影の下に青緑の境界面が現れ、背面支持体の一部が水越しに見える。Bでは、その場所が開けた空洞と支持体に変わる。海が「向こうまで見通せる空」を「厚みのある別の環境」へ変えることは確認できる。

ただし、深海の暗さ、浅瀬の明るさ、揺れる反射、都市の遠景を包む水の厚みは未検証。均一な透明材の見え方を、そのまま本物の海の光学的成立とみなさない。

## 6. 芸術的価値と海洋演出への依存度

**輪郭・大きな空洞への依存度：比較的低い。** Bにも主構成は残る。海の青を取り去った途端に全体が無意味になるモデルではない。

**内部の異世界性への依存度：高い。** Aの海は、空洞に別の環境を挿入し、向こう側の見え方と距離感を変える。Bでは大きな柱と庇の空間へ戻る。この違い自体は構想に適合する。

**建築美術の不足を水で補っている度合い：まだ無視できない。** 斜視では海の色面が主役になりやすい。Bで明らかになる背面支持体の単調さ、上下質量の相似性、公共施設の箱状反復は、水の演出では解決しない。

**光学演出が完成した場合の価値：未判定。** 今回の材質は検証用であり、美しい水レンダリングの達成を評価根拠に使っていない。

最大の成果は、「海による断層が、複数標高の公共都市前面と上部都市の下面を同時につくる」という断面原理を、実3Dで比較可能にしたこと。一方、前回の文章が述べた、海辺から深海までが生活の中につながる体験は、まだ立体で十分に再現できていない。

**総合は合格扱いにしない。** 研究モデルとして成立し、次の形態修正の根拠は得られた。現行形状への正式採択を勧める結果ではない。

## 8. 実現可能性の区分

### デジタル上で今回実現したこと

静的な主建築、数百m級施設の配置、海の体積、固定カメラ、同一モデルの比較、GLBとBlenderシーンの保存。後続で寸法・断面を変更できる再制作スクリプトも残した。

### 未来文明の仮定に属すること

開放された立体輪郭に海を保持すること、非水平な海洋領域の安定、数kmの上部都市の支持、長大な施設の荷重・振動制御。これらは世界観上の前提として扱い、実現可能な現代技術だとは主張しない。

### 今回検証していないこと

構造安全性、海の圧力・漏出・気象、生態系の持続、設備、交通容量、避難、全施設への実用的なアクセス。美術モデルのメッシュ交差は建築接合の証明ではない。特に斜面と水平段丘の接続は次工程で断面の再設計が必要。

## 9. Minecraft：忠実再現・近似・困難の切り分け

対象エディションとバージョンは未指定。既存ワールドは開いておらず、コマンド・データパック・Mod・施工は作成していない。

| 区分 | 対象 | 判断 |
|---|---|---|
| 形状として忠実に翻訳できる部分 | 主質量の輪郭、海のための空洞、四公共段丘、施設の相対位置、庭園、交通経路の見た目 | 十分な空間と解像度がある前提で、静的ボクセル形状へ翻訳可能。実縮尺での標準ワールド施工の可否とは別 |
| 近似表現が向く部分 | 地殻の曲面、丸い切り口、海洋空間の外形 | 階段状のブロック形状で輪郭を保つ。縮小率が大きいほど厚みと陰影の関係が失われやすい |
| 海の視覚的近似 | 透明・半透明の着色材、限られた水域、見せるためのモデル | 本物の遊泳可能な海とは区別する。ガラスの層を増やすと格子や濁りが勝つ可能性があり、実機検証が必要 |
| 通常の水でそのまま忠実再現しにくい部分 | 斜めの巨大自由水体、露出した海の側面、自由な三次元の輪郭 | 通常の水は周囲の空気ブロックへ広がるため、保持境界なしの同一輪郭は期待しない。透明境界を使う場合も水槽的に見える問題が残る |
| 追加技術の検討対象 | 表示専用モデル・表示エンティティ・描画変更・独自の保持挙動 | 選択肢であり、性能や忠実性は未検証。大量配置を当然の解法としない |
| 現段階で難しいこと | 原寸約4.3kmの高さ、数kmの透過表示、実際に遊泳できる斜海、巨大都市と海の同時稼働 | ワールドの垂直範囲、描画距離、透過、チャンク、流体更新を分けて検証する必要がある |

公式資料では、Java 1.18で導入されたOverworldの建築範囲は384層。この標準範囲を前提に1m＝1ブロックで高さ約4.3kmを収めることはできない。単純に高さだけを収めるなら約1:12以上の縮小が目安だが、その時点で歩行者の尺度と都市生活の細部は変質する。現在の対象環境の仕様確認なしに施工案へ進まない。

Javaの表示エンティティは位置・回転・拡縮を与える視覚表現の選択肢だが、自由水体の流体挙動や遊泳を自動的に提供する機能ではない。ここからの適用可能性は設計上の推論であり、本シーンで検証済みの実装ではない。

## 10. 次に直すべき主構成

1. **海の上縁と上部外形を部分的に切り離す。** 同じ斜線を二重に追う構図を弱め、図書館・研究・上部居住の違いが大きな肩や空洞をつくるようにする。
2. **海の前庭を、広場と街区の厚みへ変える。** 長い観覧面を一様に延ばさず、海に近づく広場、後退する生活街路、海を見ない中庭を大きな単位でつくる。
3. **背面を第二の都市正面として設計する。** 三本の支持体の反復から、物流・交通・居住を含む深い都市地形へ発展させる。
4. **海を一枚の面に読ませない。** 水の厚み・浅瀬・入り江と建築の前後関係を、材質ではなくメッシュの空間構成で強くする。
5. 同じA/B手法で再比較し、海なしでも大きな質量・空洞・街区の関係が魅力を持つ段階に達してから、海の光を研究する。

## 11. 再制作

`reproduce.ps1`をPowerShellで実行する。Blenderの場所が異なる場合は引数で渡す。

```powershell
.\reproduce.ps1 -BlenderPath 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe'
```

この手順は、同フォルダにシーン・画像を再生成する。外部アセット、ネットワーク、高精度流体は不要。Pillowを利用できるPythonがあれば、比較ページと一覧画像も再生成する。既存の研究原本やワールドにアクセスしない。

`iterations/01`には、上下の質量が均一な板に見え、海が隠れすぎた初回斜視を記録した。最終比較には使用していない。今回の形状修正後も残った問題は、上記評価で明示した。
